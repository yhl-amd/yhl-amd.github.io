概况

A 的关键指标；选了 B 时下面一行是 B 相对 A 的变化。表格是全部运行（不同并发档）的横向对比。

全部运行

CPU 时间线（只用 CPU 埋点，不开 profiler）

CPU 视角：阻塞时长 = GPU 未就绪（host 在等），未直接测 GPU。数据来自 sched/hook/atom_dash_spans.py（ATOM_DASH_SPANS=1），可跑满 10 分钟压测。泳道 = 进程 / rank：每个引擎拍、每次 worker 前向画成一格，格内按阶段堆叠；在概览条上拖动缩放。逐 span 细节用 spans_to_trace.py 导出到 ui.perfetto.dev。

步时间线（torch profiler 窗口）

每个 DP rank 一行：上半格是 CPU 侧一次 ATOM::forward（含 prepare 等待），下半格是 GPU 侧模型前向区间（decode/prefill 注解）与 DSpark 草稿区间；两步之间的空白就是引擎核（调度、DP 同步、IPC、输出处理）占的非前向时间。在上方概览条上拖动选择时间窗。

DP 均衡

DP attention + EP MoE 下各 rank 每步都要在 MoE 集合通信处对齐，步长由最慢 rank 决定。上：trace 窗口里逐步的 token 不均衡（max/mean）、GPU 起步时差、估算的不均衡损失；下：整段压测里路由到各 rank 的请求、在途请求与排队 prefill token。

请求负载（整段压测）

横轴是发压后秒数（悬停显示北京时间）。在任一折线图上拖动可设全局时间窗，所有图同步。

请求生命周期

客户端（压测工具）统计的 TTFT / TPOT / 端到端时延 / ISL / OSL 分布；服务端逐请求的 排队→首次调度→首 token→完成 由 hook 采集。

prefill 放行（PrefillDelayer / adaptive）

日志里每 1000 次决策打一行累计统计，这里转成每个区间的放行原因构成与 hold 比例；adaptive 的 T0/A 拟合值随时间变化。逐次决策（原因、hold 了几拍、全局待放行 token、哪些 rank 缺 prefill）来自 hook。

MoE 专家负载

层 × 专家的 token 计数热力图、每个 EP rank 收到的 token（dispatch 负载）、负载不均系数（max/mean）随时间变化。

DSpark 投机解码

日志 [MTP Stats Interval]（每 rank 每 1000 次验证一行）汇总的接受长度分布与接受率；trace 里每步草稿宽度。

引擎核逐步分解（hook）

每个 DP rank 的引擎核每一拍：DP 状态同步（gloo all_reduce=对齐屏障）、调度（含 delayer 的 all_reduce）、前向（含等待输出）、输出处理、其它；以及 running / waiting / KV 使用率。
