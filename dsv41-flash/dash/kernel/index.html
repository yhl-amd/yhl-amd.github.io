按 batch、token 长度、KV 长度切换，看 prefill / decode 一步里每个算子、每个 kernel 的 GPU 时间。算子表沿用 DeepSeek-V4.1-Flash 图解里的 ATOM 算子调用图；kernel 归类规则在 mapping.json，数据由转换脚本从 torch profiler / rocprofv3 trace 生成。

示例数据（合成），非真实测量。 页面里的数据集“示例 X / 示例 Y”由玩具代价模型和随机数生成，kernel 名都是占位名（kernel_<算子>_a），只用来展示看板的结构和交互，不代表任何硬件或软件的性能。点“加载数据文件”可选择本机的数据集 JSON、打包好的 bundle.js（含 mapping 时一并替换）或 mapping.json；文件只在浏览器里读取，不会上传。

1 · 一层的 kernel 流程架构图

从上到下：prologue（H2D、embedding、Engram）→ 层前置 → attention 半层（主路径 / 压缩器 / indexer 三条泳道）→ FFN 半层（routed MoE / shared expert 两条泳道）→ epilogue（lm_head、采样、验证）→ DSpark（草稿 KV、3 个草稿块、草稿头）。每个节点：算子名、最耗时的 kernel、GPU 时间（µs/步）、占本步比例、每步调用次数；底色越深越耗时。点节点看 kernel 明细和利用率估算。
